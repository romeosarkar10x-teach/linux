# 00/01 — Exercises

No lab directory for this lesson; the container doesn't exist yet. Work in a text file on your
host or in the VM, and keep it — the validator will ask for it.

Save your answers as `00-01-answers.md`.

---

## Warmup

**1.** Without looking back at the notes, list the six exercise tiers in order and write one
sentence on what each is for.

*Done looks like:* six named tiers, six sentences, in `00-01-answers.md`. Then check yourself
against the notes and mark anything you got wrong — don't quietly fix it.

**2.** Name the six files in a lesson directory and mark which two you are meant to read.

*Done looks like:* six filenames, two marked.

---

## Core

**3.** Write down, in your own words, why this course refuses to let an agent give you the answer
even when you're stuck and short on time. Then write the strongest argument *against* that policy
you can think of.

*Done looks like:* two short paragraphs. The second one should be genuinely persuasive; if it
isn't, you haven't understood the tradeoff, only the rule.

**4.** Open [`SYLLABUS.md`](../../SYLLABUS.md). Find three topics marked `(review)` or `(review+)`
that you believe you already know cold, and three unmarked topics you've never heard of. Write both
lists.

*Done looks like:* two lists of three, with the chapter/lesson numbers. Keep this file — you'll
re-read it after Chapter 15, and the "I know this cold" list is usually humbling.

---

## Experiment

**5.** **Predict first, in writing.** You'll be asked to keep every failed command in your shell
history as evidence. Before reading further or trying anything: write down what you think a
validator can tell from a history file that it *cannot* tell from your finished lab directory
alone. List at least three things.

Then read the "Evidence, in priority order" section of
[`docs/VALIDATION_PROTOCOL.md`](../../docs/VALIDATION_PROTOCOL.md).

*Done looks like:* your prediction, then the actual list, then a sentence on what you missed and
why you missed it. If you missed nothing, say which item you were least confident about.

---

## Dig

**6.** This course sends you to `man` constantly, so start now — on your host or in the VM, before
the container exists.

Run `man man`. Find the answer to: **what are the numbered sections, and which one holds file
formats and conventions?** Then find how to open a page from a *specific* section.

*Done looks like:* the list of sections with one-word descriptions, the section number for file
formats, and the syntax for requesting a section explicitly. Say which part of the man page you
found each in.

> Hint on technique, not answer: inside `man`, press `/` to search, `n` for the next match,
> `q` to quit. Learn those three keys now; you'll use them for the rest of your career.
