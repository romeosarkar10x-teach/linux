## The mechanism (13–24)

13. Yes. `ls -d <literal path>` has no glob in it, so nothing filters it.
14. Yes — `02-navigation` is written literally; only the `*` after it expands,
    and `README`/`deck-map.txt` are not ignored names.
15. No: `echo *` prints four names. The **shell** expands `*`, and it removes
    ignored names before any program sees them. `ls`, `echo` and `rm` all get
    the shortened list and none of them can tell. Exercise 13 works because
    there was nothing for the shell to expand.
16. Yes, fully readable.
17. Nothing is wrong with the directory. One account's shell is configured not
    to produce its name.
18. `homes/dorn/.config/kestrel/env.sh:8`.
19. Because `.bashrc` does not contain it — it *sources* the file that does.
    `grep -rn GLOBIGNORE homes/dorn/` (recursive, and note the dot-directory)
    is what finds it. A single-file grep is a test of one hypothesis; an
    incident needs the recursive one.
20. `.profile` → `.bashrc` → `.config/kestrel/env.sh`.
21. Two lines:

        GLOBIGNORE='02-navigation:02-navigation/'
        alias ls='ls --hide=02-navigation'

    `GLOBIGNORE` removes the name from every glob expansion. The alias covers
    the case where no glob is involved at all — a bare `ls` with no arguments,
    which is what cass ran. Fixing either one alone leaves the other. That is
    why the checker tests both, and why finding one is not finding it.
22. `type ls` → ``ls is aliased to `ls --hide=02-navigation'`` — that is the one
    that tells you the truth. `\ls` and `command ls` both bypass the alias and
    list all five, but they only show you that something is wrong, not what.
    None of them says anything about `GLOBIGNORE`; that half is invisible to
    `type` because it is not a command at all.
23. `bin/name-mechanism GLOBIGNORE .config/kestrel/env.sh` →
    `STAGE{two-mechanisms-one-file}`.
24. The account owns it; the toolchain writes it and never reads it back; it has
    never compared one account's file against another's. So anyone who can write
    to a home directory can put anything in a file that is *presumed generated*,
    and no process on the station will ever notice. "Generated" is a social
    fact, not a technical one.

## The repair (25–33)

26. Because the file's first line says it is regenerated on upgrade. Delete the
    lines and the repair survives exactly until the next upgrade, at which
    point the account quietly goes back to not seeing the archive and nobody
    is watching for it. A repair that an upgrade undoes is a delay.
27. The `.` of `env.sh` happens partway through `.bashrc`; `PS1` is assigned
    after it. So `.bashrc` gets the last word, and lesson 05's rule applies:
    the last assignment in a file wins.
28. Append to `.bashrc`, after the sourcing block:

        # env.sh is regenerated by the toolchain and hides archive section 02.
        # We cannot edit it and keep the fix, so we override it here instead.
        unset GLOBIGNORE

29. `bin/verify-repair` rejects: globbing is fixed, `ls` is not.
30. Because the alias is a second, independent mechanism. `unset GLOBIGNORE`
    says nothing about aliases. Add:

        unalias ls 2>/dev/null

    (`2>/dev/null` because on a shell where the alias was never defined,
    `unalias` complains — and a startup file that prints errors is its own
    small incident.)
31. `bin/verify-repair` → `STAGE{last-line-wins}`.
32. `423edca9f8d10d158b52dbb51727c871` — unchanged.
33. `HOME=$PWD/homes/dorn bash -l`, then `ls "$ARCHIVE"` and `cd "$ARCHIVE";
    echo *`. Five each.

## Write-up (41–50)

41. For example: "The directory was never missing. Your colleague's account has
    a startup file that tells their shell to leave `02-navigation` out of `ls`
    and out of every `*`. The shell did what it was configured to do and neither
    of you was shown any indication that a filter existed."
42. Yes, and she should not have to like it. Directory contents are read by a
    program; what she sees is what her shell chose to pass on. Two shells,
    two configurations, two truthful answers.
43. `find archive -maxdepth 1`, or `ls -d archive/02-navigation`, or `type ls`.
    Not unreasonable to miss: every one of those is a command you only reach for
    once you already suspect your own tools, and suspecting your own tools is
    the last thing anyone does.
44. Yes. The upgrade rewrites `env.sh` with the same two lines; `.bashrc` still
    sources it and still overrides it afterwards. That is the point of fixing it
    downstream rather than upstream.
45. A bare `unset GLOBIGNORE` at the end of a `.bashrc` is a mystery to the next
    reader and will be deleted by someone tidying up. Two comment lines naming
    the file it counteracts and why are part of the repair.
46. (a) `.bashrc` is read by people; `.config/kestrel/env.sh` is read by nobody,
    because everything about it says "generated, don't look". (b) A search for
    the string in the obvious file finds nothing, and dotted config directories
    are skipped by careless greps and by `ls` without `-a`. It is hidden by
    convention, not by permissions — which is why permissions did not help.
47. The account owns it. Who *could* have written it: the account, or root. Who
    *did*: not answerable from what is in this lab, and you should not answer
    it. The timestamp, the fact that it does not match the file's own claim, and
    the fact that it hides exactly one thing are what you report.
48. The toolchain never compares one account's generated file to another's. A
    checksum of every generated file at generation time, compared on upgrade,
    would have caught it — a few lines and a table, and the reason it does not
    exist is that nobody expected the generated file to be interesting.
49. `find` and `grep -r` read directories through the kernel and act on what is
    there. `ls` printed exactly what it was asked to print by a shell that had
    been told to remove one name, with a flag it was handed. Nothing lied.
    `ls` was *given a shorter question*, and answered it accurately.
50. Hidden is a property of the file — a leading dot, a mode, a location.
    Invisible-to-one-person is a property of a *view*, and the file has no idea
    it is happening. Only the second one can be true for one person and false
    for another at the same instant.
